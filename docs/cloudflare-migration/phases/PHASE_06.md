## Initial design decisions (local proof, not release format)

Keep the archive codec outside Worker request paths. No auth credentials, session tokens, passkeys, secret configuration or raw databases as export inputs; allow only explicitly selected workout-state snapshots and known media inventory. A caller must establish source ownership and enumerate all required snapshots and retained objects; codec verifies supplied known inventory, cannot discover devices or identify arbitrary sensitive fields in state. Separate random 256-bit recovery key, AES-256-GCM with version-bound AAD; reject without authenticated payload. Bound total archive/individual file/snapshot count, refuse oversize instead of truncating. This increment deliberately bounds memory for synthetic qualification; production-capacity streaming/export design and independently durable key storage remain open. Treat retained and local-only bytes as preservation obligations, not upload authorization. Quota ledger is read-only conservative accounting of supplied owner-bound inventory, not Cloudflare billing/available account capacity or deletion permission. No restore writes in first increment; later independently qualify actual destination revision, ownership, capacity, safe interrupted restore and verified readback. All implementation claims require tests; no production secrets/data or backup bytes in CI artifacts/logs.

### Recovery and privacy runbook — local design, not production instructions

1. Before any future real recovery, freeze writes and enumerate owner-bound source state/revision/write identity, retained R2 media, every device/stash/active and local-only copy. Unreadable or missing inventory is a stop condition, not an empty list. Never export auth tables, cookies, bearer tokens, passkey credentials, setup/signing secrets, or raw databases. State may itself contain private information; review schema and allowed export content before a production tool is authorized.
2. Independent high-entropy recovery key must not be derived from or stored alongside signing/setup secrets or archive. Record recovery-key custody, tested retrieval, rotation/version and loss handling; do not log keys, private media, snapshot payloads or recovery secrets. Local key-file fixture is not evidence of off-provider backup or secure production custody.
3. Publish only authenticated verified archives without overwrite. For an ambiguous write, inspect the existing final archive using the correct owner/key and compare expected digest; never delete/rewrite on uncertainty. Retain prior independently verified versions. Reject missing bytes, incompatible size, corrupt archive or unavailable destination; do not discard oversized originals or promise successful cutover.
4. Verify source/destination owner, revision, inventory and capacity before restore; stage and verify all bytes before any state publish. On interrupted upload reconcile by actual readback and resume idempotently, never blindly retry state overwrite. New owner mapping must be explicit and authorized. Existing-account and stale writes remain prohibited until dedicated fencing/restore contract qualified. No silent resurrection after intentional erasure.
5. Reset with retention remains approved: server media remains and counts toward quota; only report actual verified results, never claim deletion. Separate account erase remains explicit intentional operation with truthful pending/backup/offline disclosure. Automatic/selective purge remains unavailable. Existing official-client pending/cache and reset cleanup gates remain deferred; no release or cutover until all acceptance holds resolved.
